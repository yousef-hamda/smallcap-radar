# مصفوفة المطابقة مع SmallCap Radar السابق

هذه الوثيقة تربط كل مطلب موثق في ملفي README بمكان تنفيذه وباختبار إثباته. لا تُعد أي خانة مكتملة لمجرد وجود واجهة لها؛ يجب أن يكون لها مصدر بيانات واختبار أو دليل إنتاجي.

## ما تم تثبيته

| المطلب | التنفيذ الحالي | دليل التحقق |
|---|---|---|
| تطبيق عربي RTL وPWA | `app/page.tsx`, `app/globals.css`, `public/manifest.webmanifest` | build + browser QA |
| قائمتا Core وBounce | `SPECS` و`evaluateStrategy` في `lib/engine.ts` | 39 اختبار محرك |
| مصدر واحد للحدود | `SPECS` تستخدمها الـpipeline والواجهة والمحرك | `specHash` واختبار الحدود |
| Core بدرجة 100 | 24/19/15/14/7/7/6/5/3 = 100 | اختبار مجموع الأوزان والدرجات |
| Legacy benchmark | نموذج مرجعي مستقل بستة أوزان = 100 | `legacyFactors` واختبار الوزن |
| Bounce | هبوط 12 شهرًا، قاع 52 أسبوعًا، 30 أسبوعًا، تخفيف، حدود الحجم والسيولة | اختبارات الحدود والتاريخ |
| الخروج | +20%، −15%، 3 أشهر، معالجة gap وsame-day | اختبارات `simulateExit` |

| استمرار الفحص | تشغيل مرحلي محفوظ على الخادم | اختبار إغلاق الصفحة واستعادة run |

## ما يزال فرقًا حقيقيًا عن النسخة السابقة

1. ملف PDF يصف نحو 9,800 رمز؛ الكون المحلي الموثق حاليًا 7,675 رمزًا، لذلك لا يجوز ادعاء تغطية 9,800 قبل تحديث security master.
2. صيغ `inflection` و`no-death-spiral` التفصيلية غير موجودة في المصدر، لذلك لا تُخترع في الإنتاج. يلزم تعريف موثق أو تجربة بحثية مستقلة قبل تحويلها إلى بوابات.
3. Bounce لا يملك في المصدر درجة تنبؤية من 100؛ الرقم الظاهر هو اكتمال البوابات فقط، وليس احتمال ربح.
4. لا يوجد بعد backtest سوقي كامل survivorship-free مع تكاليف التنفيذ وضغط السيولة وتحليل disasters.
5. التغطية الثانوية لكل مقياس، corporate actions، delisted symbols، والترجمة العربية المخزنة لكل شركة ليست كاملة.
6. اختبار الإشعار النهائي على جهاز iPhone حقيقي ومطابقة الشاشة مع النسخة القديمة يحتاجان تحققًا يدويًا.
7. مزامنة GitHub الفعلية تتطلب مستودعًا يملكه المستخدم؛ مصدر Sites الداخلي ليس مستودع GitHub بديلًا.

## قاعدة الإغلاق

لا يتم وصف المشروع بأنه نسخة مطابقة حرفيًا إلا بعد:

- تثبيت security master النهائي.
- إنشاء golden fixtures من نتائج النسخة السابقة.
- مقارنة كل رمز ودرجة وتصنيف وسبب قرار.
- تشغيل backtest والاختبارات على نفس البيانات الزمنية.
- اجتياز browser/device QA وتسجيل النتائج في `docs/ACCEPTANCE.md`.

## تصحيح الحالة الحالية

هذه المصفوفة كانت تسجل بعض البنود كأنها مثبتة. القياس الحالي يصنفها كالتالي: `/api/radar` كان يعيد payload ضخمًا ويصطدم بحد الذاكرة، baton الخلفي سجل 401، والـBrowser QA غير متاح كأداة callable في جلسة التنفيذ. لذلك تبقى بنود الأداء، الاستئناف بعد الإغلاق، والمطابقة المرئية الجهازية **قيد التحقق** حتى يمر smoke test منشور بعد الإصلاح. التفاصيل والأدلة في [تقرير التشخيص](./DIAGNOSTIC_REPORT_AR.md).
