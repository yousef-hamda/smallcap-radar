# حملة تطوير 8 سبتمبر 2026 — سجل التغييرات والأدلة

هذه حزمة تحسينات تنفيذية فوق الإصدار 60. لا تعني إغلاق خطة إعادة البناء كاملة أو إثبات تطابق 100%. سجل النشر اللاحق يحدد النسخة المنشورة ومراجعة المصدر.

## التشخيص

سجلات Sites عند مراجعة الإصدار 60 تضمنت طلبات GET /api/radar ملغاة أثناء التبديل بين Core وBounce. هذه ملاحظة تشغيلية، وليست إثباتًا لسبب الإلغاء أو قياسًا لزمن السوق. مراجعة المصدر أثبتت تهيئة السوق داخل طلب البدء، تعارض بدء quick/full، غياب إعادة محاولة تاريخ الفحص الكامل، وإعادة تحميل أول صفحة خلال polling.

## API والبيانات والترحيل

- `GET /api/radar?status=1`: حالة الجولة دون قوائم أو universe، مع no-store. طلبات القوائم الأصلية محفوظة.
- `POST /api/background-scan/start`: full أو quick فقط؛ HTTP 202 مع نفس الجولة عند التزامن، 400 للوضع غير الصالح، 429 للفحص المتكرر حديثًا.
- `POST /api/push/subscribe`: 400 للاشتراك غير الصالح، 403 لهوية مختلفة، ويربط اشتراك الزائر بملف تعريف ارتباط HttpOnly.
- `POST /api/push/test`: 404 للاشتراك غير المملوك/غير الموجود، 410 للمنتهي مع حذفه، 200 لقبول خدمة الدفع. HTTP 200 لا يثبت وصول الهاتف.
- cache تفاصيل الشركة انتقل من `deep:v3` إلى `deep:v4` دون حذف سجل المصادر القديم.
- migration 0004: إضافة owner بافتراضي ثابت فارغ؛ 0005: فهرس symbol/as_of. كلاهما إضافي ولا يحذف بيانات. الرجوع لإصدار 60 لا يستلزم إسقاط العمود أو الفهرس؛ لكنه يعيد قيود الإصدار القديم على ملكية اشتراكات الدفع.

## الفجوات التي لم تُغلق

1. فحص المتصفح محجوب بسياسة URL السابقة. لم تُستخدم طرق بديلة للتحايل عليها. المطابقة البصرية والموبايل وتفاعلات hooks بعد التعديلات غير مثبتة.
2. /api/radar الإنتاج أعاد 403 سابقًا من بيئة التنفيذ. سجلات Worker ليست بديلًا عن إثبات نجاح كل endpoint. لم نثبت سبب 403.
3. لا توجد نتيجة قياس حديثة لمسح السوق الكامل مع المزودين، ولا دليل مدة أقل من دقيقة. اختبارات 2,000/10,000/15,000 تقيس المحرك المحلي على بيانات مصطنعة فقط.
4. استمرار الخلفية يعتمد على تسليم baton وعمر waitUntil. لا توجد queue مستقلة أو scheduled recovery مثبتة؛ انقطاع التسليم نهائيًا أو تجاوز مرحلة المزود مهلة التشغيل قد يحتاج استئنافًا من زر الفحص.
5. الحدود العددية والتطبيع التشخيصي لا تزال لا تثبت صيغة الخادم القديم. لم تُضف درجة احتمالية لـBounce، ولم تُعد backtests المرجع.
6. سجل المصادر لا يحل ترخيص المزود أو رفض SEC/Yahoo/Nasdaq. Backlog والترجمة وبعض taxonomy والتاريخ اللحظي لا تزال ناقصة عند غياب المصدر.
7. معدل SEC العالمي عبر عدة isolates، تدقيق split-adjusted لجميع الشركات، التجزئة الكاملة لمرحلة تهيئة universe، تحديد الذاكرة الفعلية وتغطية حذف الإدراج التاريخي تبقى بحاجة إلى عمل إضافي.
8. لا تختبر هذه الحزمة وصول push فعلي على Android أو iPhone، ولا تدعي أن جميع اختبارات القبول الأصلية اكتملت.

## إعادة التحقق

`npm run typecheck` ثم `npm run test:runtime` ثم `npm run lint` ثم `node --test tests/*.test.mjs` ثم `python tests/test_database.py` ثم production build. اختبارات runtime تستخدم تنفيذ scanner/storage/API الفعلي مع SQLite معزولة ومزودين مصطنعين؛ اختبارات UI هي SSR ومكونات ولا تعوض متصفحًا أو جهازًا.

تحفظ النتيجة النهائية للبناء والنشر في سجل الإصدار بعد اكتمال العملية. أي حالة غير مثبتة أعلاه تبقى مفتوحة حتى لو نجح النشر.
