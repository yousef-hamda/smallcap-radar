# Small-Cap Radar V2 — الدليل المرجعي الكامل

هذا الملف هو المرجع التشغيلي والتقني للمشروع. يشرح ما الذي يفعله التطبيق، كيف تُجمع البيانات، كيف تُحسب البوابات والدرجة، كيف تستمر عملية الفحص بعد إغلاق الهاتف، وما الذي تم اختباره فعليًا. لا يجوز اعتبار أي حقل غير متاح حقيقةً؛ القاعدة في كل النظام هي أن `UNKNOWN` تعني «لا توجد أدلة كافية»، ولا تتحول إلى نجاح.

## 1. هدف المنتج

Small-Cap Radar ليس توصية شراء آلية. هو نظام بحث يحوّل كونًا كبيرًا من الأسهم الأمريكية إلى قائمة قصيرة تستحق المراجعة البشرية:

```text
دليل الأسهم → تنظيف الأوراق المالية → أسعار جماعية → أساسيات SEC
→ بوابات Core/Bounce → درجة تشخيصية → تحقق عميق عند فتح السهم
→ قائمة مؤهلة قابلة للتدقيق
```

كل نتيجة مرتبطة بلقطة زمنية، مصدر، نسخة مواصفة، وسبب كل قرار. لا يسمح النظام لدرجة مرتفعة بإنقاذ سهم فشل بوابة أساسية.

## 2. تجربة المستخدم والواجهة

- واجهة عربية RTL، داكنة، متجاوبة، وMobile-first.
- عند فتح التطبيق تظهر آخر لقطة مكتملة محفوظة؛ لا يبدأ فحصًا جديدًا تلقائيًا.
- القائمتان الرئيسيتان هما **فرص الارتداد** و**القيمة الأساسية**.
- توجد قائمة مستقلة اسمها **قائمة المتابعة/المفضلة**.
- لا تُعرض «مؤهلة» و«مستبعدة» كوجهتين رئيسيتين للمستخدم.
- البحث يعمل بالرمز أو الاسم.
- كل بطاقة تعرض الرمز، اسم الشركة، السعر، التغير، السوق، القيمة السوقية، الدرجة، وشارات البوابات.
- الضغط على البطاقة يفتح ملفًا تفصيليًا يحتوي السعر، المؤشرات المالية، الرسم، البوابات، الأدلة، الأخبار، الهدف التحليلي والمصادر المتاحة.
- الحقول غير المتاحة تظهر بوضوح كـ`—` أو «غير متاح»؛ لا توجد أرقام تجميلية مصطنعة.
- المفضلة محفوظة في قاعدة البيانات وتبقى بعد إعادة فتح التطبيق.

## 3. الاستراتيجيات

يوجد محرك واحد مشترك، وتقرأ منه ثلاث مواصفات:

| النموذج | الاستخدام | الحالة |
|---|---|---|
| Legacy | خط أساس للمقارنة مع النظام القديم | Benchmark فقط |
| Core Value V2 | شركات صغيرة، رخيصة، قابلة للبقاء، أفق 12–24 شهرًا | إنتاجي مشروط بالبيانات |
| Bounce V2 | هبوط كبير قرب القاع مع شروط ارتداد وخطة خروج | إنتاجي مشروط بالبيانات |

كل حد رقمي يُعرّف مرة واحدة داخل `lib/engine.ts` وتقرأه مرحلة الفحص والواجهة والاختبارات. لا يسمح التصميم بوجود Threshold مختلف في ملف آخر.

## 4. Legacy Benchmark

المرجع القديم الموثق:

- القيمة السوقية: `$50M–$5B`.
- متوسط حجم التداول بالدولار: لا يقل عن `$300k/day`.
- السعر إلى المبيعات: `P/S ≤ 10`.
- صافي الدخل موجب **أو** التدفق النقدي الحر موجب.

الأوزان المرجعية مجموعها 100:

| العامل | النقاط |
|---|---:|
| التقييم | 25 |
| الربحية/FCF | 20 |
| الزخم | 20 |
| التخفيف | 15 |
| الحجم | 10 |
| الشراء الداخلي | 10 |

يبقى Legacy داخل مختبر المقارنة ولا يُستخدم وحده لتقديم قائمة شراء.

## 5. Core Value V2

### البوابات الأساسية

1. سهم عادي قابل للتداول في سوق أمريكي.
2. القيمة السوقية بين `$25M` و`$2B` شاملًا الحدين.
3. سيولة تشغيلية: median لحجم التداول بالدولار خلال 20 يومًا لا تقل عن `$150k/day`.
4. وجود إيرادات فعلية قابلة للتحقق.
5. `EV/S ≤ 10` عند توفر القيمة السوقية، النقد، الدين، والإيراد بشكل صالح.
6. ربحية أو تدفق نقدي حر موجب. فرع «الانعطاف إلى الربحية» لا يُخترع عند غياب تعريف موثق.
7. لا تُمرّر مخاطر دوامة تمويل غير محلولة؛ الحالة غير المثبتة تبقى `UNKNOWN`.
8. حداثة وتوافق المصادر ضمن قواعد freshness/conflict.

### الدرجة التشخيصية من 100

الأوزان الحالية: `24 + 19 + 15 + 14 + 7 + 7 + 6 + 5 + 3 = 100`.

| العامل | الحد الأقصى | المعنى |
|---|---:|---|
| التقييم | 24 | رخص EV/S أو مقياس بديل موثق |
| الجودة والربحية | 19 | Net Income أو FCF واتجاه الجودة |
| انضباط الأسهم | 15 | التخفيف وعدد الأسهم |
| الحجم والتغطية | 14 | الحجم وتوفر الأدلة |
| النمو | 7 | نمو الإيرادات ضمن نطاق محافظ |
| الشراء الداخلي | 7 | Form 4، كود `P` فقط |
| اتجاه الهوامش | 6 | تحسن هامش التشغيل |
| نقطة الدخول | 5 | تجنب الدخول بعد حركة متطرفة |
| الميزانية | 3 | صافي النقد/الدين |

الدرجة تشخيصية وليست احتمال عائد. إذا غابت عوامل حرجة أو فشلت بوابة، فلا يدخل السهم قائمة الموافقة حتى لو كان مجموع النقاط مرتفعًا.

## 6. Bounce V2

Bounce يبحث عن فرصة ارتداد لا عن شركة قيمة طويلة الأجل. البوابات تشمل:

- هبوط 12 شهرًا ضمن الحد الموثق.
- قرب السعر من قاع 52 أسبوعًا.
- توفر 30 إغلاقًا أسبوعيًا مكتملًا لحساب MA30W.
- شروط السعر مقابل MA30W.
- تخفيف الأسهم ضمن الحد المسموح، مع مراجعة مستقرة لعدد الأسهم.
- سيولة median بالدولار خلال 20 يومًا لا تقل عن `$150k/day`.
- حجم السوق وشروط السهم العادي.

خطة الخروج المحافظة:

- هدف: `+20%`.
- وقف: `−15%`.
- انتهاء: ثلاثة أشهر تقويمية، مع ضبط نهاية الشهر وأول افتتاح تداول متاح.
- إذا لمس السعر الهدف والوقف في الشمعة نفسها، يُفترض تنفيذ الوقف أولًا.
- فجوة تحت الوقف تُنفذ عند الافتتاح.
- لا توجد شموع مستقبلية تعني خروجًا وهميًا؛ النتيجة تكون «مفتوح».

لا توجد في المصدر القديم معادلة تنبؤية معتمدة لدرجة Bounce من 100؛ لذلك تُعرض أهلية البوابات واكتمالها، لا احتمال ربح مختلق.

## 7. دورة البيانات والفحص

### 7.1 الكون والتنظيف

يُحمّل دليل SEC/Nasdaq، ثم تُستبعد الأدوات غير المناسبة مثل ETF، الصناديق، الـtrust، warrant، right، unit، preferred، bond وLP. التنظيف المحافظ لا يساوي بعد Security Master تجاريًا كاملًا.

### 7.2 الأسعار الجماعية

تُطلب الأسعار في دفعات كبيرة (حتى 250 رمزًا لكل طلب عند استخدام المسار الجماعي)، مع السعر، القيمة السوقية، الحجم، القطاع، الصناعة، وحقول 52 أسبوعًا عند توفرها.

### 7.3 SEC Frames

تُجمع مجموعات XBRL الرسمية بالجملة، بما في ذلك بدائل IFRS عند الحاجة. تُستخرج الإيرادات، الدخل، التدفق النقدي، النقد، الدين، وعدد الأسهم وفق الفترة الصحيحة. لا تُعامل فجوة تغطية SEC كصفر.

### 7.4 إثراء Bounce

بعد اللقطة الجماعية فقط، تُطلب بيانات Nasdaq التاريخية للمرشحين لحساب return12m وlow52w وMA30W. تُحفظ provenance لكل قيمة. التاريخ الكامل لا يُخزّن داخل صف المسح؛ يُجلب عند فتح ملف الشركة لتقليل حجم قاعدة البيانات.

### 7.5 الاستئناف والعمل في الخلفية

لكل فحص `run id`، ومرحلة، وoffset، وطابور إعادة محاولة، وlease. المتصفح يطلب خطوات محدودة، لكن حالة الفحص محفوظة على الخادم. عند إغلاق التطبيق يمكن للـWorker مواصلة السلسلة، وعند العودة تُستعاد آخر نتيجة مكتملة بدل استبدالها بلقطة جارية ناقصة.

المراحل المنطقية:

1. إنشاء الفحص.
2. تحميل الكون وتنظيفه.
3. الأسعار الأولية.
4. SEC Frames.
5. إنشاء اللقطات الجماعية.
6. إثراء التاريخ للمرشحين.
7. حفظ الحالة النهائية، أو `partial` مع الأخطاء القابلة للتدقيق.

## 8. الحالات والنتائج

كل بوابة واحدة من:

- `PASS`: دليل صالح ويجتاز الحد.
- `FAIL`: دليل صالح ويفشل الحد.
- `UNKNOWN`: البيانات مفقودة، قديمة، متعارضة أو غير قابلة للتحقق.

القاعدة النهائية:

```text
PASS list = screeningQualified === true
UNKNOWN لا يساوي PASS
FAIL لا يمكن إنقاذه بالدرجة
```

لذلك قد تكون قائمة الموافقة فارغة إذا كانت التغطية المالية أو التاريخية غير كافية. هذه نتيجة أمان بيانات وليست سهمًا ناجحًا وهميًا.

## 9. التقييم، الأدلة، والوقت

كل Snapshot يحمل `asOf`, `availableAt`, `retrievedAt`, الفترة، العملة، المصدر، ورابط الدليل عند توفره. تُستبعد الأدلة المستقبلية. سجلات SEC ذات تاريخ يومي تُعامل متاحة في نهاية يوم الإيداع. عند تعارض مسارين موثوقين لا يُختار أحدهما بصمت؛ تتحول القيمة إلى مراجعة أو `UNKNOWN`.

التحديث التفصيلي عند فتح السهم قد يستخدم SEC Company Facts، تاريخ Nasdaq، Yahoo RSS، وبيانات Form 4. أي مصدر محجوب أو منتهي الصلاحية يظهر في سجل الأخطاء ولا يُستبدل بتخمين.

## 10. ملف الشركة

يعرض الملف، عند توفره:

- الرمز والاسم والسوق والقطاع والصناعة.
- السعر والتغير والقيمة السوقية.
- الدرجة من 100 وتغطية الدرجة.
- وصف نشاط الشركة بالعربية عند توفر وصف موثق.
- الإيرادات، صافي الدخل، FCF، EV/S، السيولة والتخفيف.
- رسم سعري بخيارات 5Y و2Y و1Y و6M و1M.
- صفوف كل معيار: الحالة، السبب، والقيمة الخام.
- متوسط هدف المحللين ونسبة الارتفاع إن وصل المصدر.
- نطاق 52 أسبوعًا، مفاجآت الأرباح، backlog، Form 4 والأخبار عندما يرد الحقل من مصدر فعلي.
- قائمة provenance وروابط المصادر.

لا يُعرض backlog أو هدف محللين أو خبر إذا لم يصل من مصدر؛ يظهر «غير متاح» بدل ملء الفراغ.

## 11. الإشعارات والتثبيت

الفحص محفوظ على الخادم ولا يعتمد على بقاء الشاشة مفتوحة. إشعار الإكمال يستخدم Web Push موقّعًا ومشفّرًا. على iPhone يجب:

1. فتح الموقع في Safari.
2. اختيار المشاركة ثم **إضافة إلى الشاشة الرئيسية**.
3. فتح التطبيق من الأيقونة.
4. الضغط على زر تفعيل/اختبار الإشعارات وقبول الإذن.

بدون هذه الخطوة لا يستطيع iOS عرض طلب الإذن كما في تطبيق أصلي. نجاح توقيع الطلب آليًا لا يساوي بعد اختبار وصول فعلي على جهاز المستخدم.

## 12. واجهات API

| المسار | الوظيفة |
|---|---|
| `GET /api/radar` | آخر فحص وحالة الفحص واللقطات المعروضة |
| `GET /api/company?symbol=...` | إثراء عميق لسهم واحد مع cache مؤقت |
| `POST /api/radar` | المفضلة أو استيراد Snapshot موثق |
| `POST /api/background-scan/start` | بدء فحص سريع أو كامل على الخادم |
| `POST /api/scan` | خطوة تشخيصية/استرداد يدوية |
| `GET /api/push/key` | مفتاح Web Push العام |
| `POST /api/push/subscribe` | تسجيل اشتراك الجهاز |
| `GET /api/export?kind=spec` | مواصفة المحرك |
| `GET /api/export?kind=schema` | مثال قاموس البيانات |

استيراد البيانات يقبل Snapshot[] فقط، بحد أقصى 500 سجل و4MB، ويرفض الرموز المكررة وprovenance غير الصالح.

## 13. قاعدة البيانات والحفظ

قاعدة D1 تُهيّئ مخططها ذاتيًا وتحتوي runs، snapshots، evaluations، fundamentals، سجل الأحداث، المفضلة، اشتراكات push، وحقول lease/retry. كل فحص يحمل hash للمواصفة، ولا تُخلط نتائج نسختين مختلفتين من المحرك. آخر فحص جارٍ لا يحجب آخر فحص مكتمل عن المستخدم.

## 14. الاختبارات المطلوبة والمنفذة

الاختبارات الحالية تشمل:

- مجموع أوزان Core وLegacy = 100.
- حدود القيمة السوقية والسيولة وEV/S.
- OR بين Net Income وFCF.
- UNKNOWN والتعارض والبيانات المستقبلية.
- split لا يُنتج تخفيفًا زائفًا.
- 30 أسبوعًا مكتملًا دون أسبوع جزئي.
- تطبيع نسب Yahoo مرة واحدة.
- تحويل الدخل السنوي والتراكمي بشكل صحيح.
- PIT وholdout وbootstrap وBonferroni.
- كل حالات الخروج: الهدف، الوقف، الفجوة، الانتهاء، وعدم وجود شموع مستقبلية.
- Web Push والتغذية الراجعة ومكونات الواجهة.

أوامر التحقق:

```bash
npm ci
npm run typecheck
npm run lint
npm run test:engine
npm test
npm run build
```

نجاح البناء لا يثبت صحة السوق. يلزم أيضًا فحص API، لقطة هاتف، اختبار إغلاق التطبيق، اختبار إشعار فعلي، ومقارنة golden fixtures مع النسخة القديمة.

## 15. ما هو مكتمل وما هو غير مكتمل

### مطبق

- واجهة عربية RTL وPWA.
- القوائم المؤهلة فقط والمفضلة.
- محرك موحد ونسخ مواصفات.
- فحص bulk quotes وSEC Frames.
- فحص تاريخ Bounce المرحلي.
- provenance وUNKNOWN وconflict handling.
- استئناف الفحص بعد إغلاق الصفحة.
- ملف شركة ورسم وAPI تصدير.
- اختبارات المحرك والبناء والنشر.

### يحتاج بيانات/اعتمادًا إضافيًا قبل ادعاء التطابق الحرفي

- استعادة dataset الأصلي غير القابل للتغيير مع الشركات المشطوبة.
- golden fixtures من النظام السابق لكل رمز ودرجة وتصنيف.
- التعريف الرياضي الأصلي لـinflection وdeath spiral ودرجات العوامل الفرعية.
- مصدر ثانٍ مرخّص ومتكامل لكل البيانات المالية.
- تغطية كاملة للمحللين، الأخبار، backlog، corporate actions والترجمة العربية.
- backtest survivorship-free كامل مع تكاليف التنفيذ وضغط السيولة.
- اختبار إشعار فعلي على جهاز المستخدم.
- مستودع GitHub يملكه المستخدم؛ مصدر Sites الحالي ليس GitHub.

لا يجوز كتابة أن التطبيق «نسخة مطابقة 100%» قبل إغلاق هذه البنود بأدلة قابلة لإعادة الإنتاج.

## 16. الأمان والأسرار

لا تُحفظ مفاتيح Cloudflare/R2 أو tokens داخل المستودع أو README أو سجل Git. المفاتيح التي ظهرت سابقًا يجب اعتبارها مكشوفة واستبدالها قبل ربط حساب Cloudflare منفصل. في النسخة الحالية تُستخدم بيئة Sites، مع حماية same-origin للعمليات؛ الاستخدام متعدد المستخدمين يحتاج هوية وصلاحيات ونطاق بيانات لكل مستخدم.

## 17. التشغيل والنشر

المشروع يستخدم Vinext/React على Sites، مع `hosting.json` وهوية المشروع محفوظة. قبل أي نشر:

1. تشغيل الاختبارات والبناء.
2. تنفيذ commit.
3. دفع نفس الـSHA إلى مصدر Sites.
4. إنشاء archive من نفس الحالة.
5. حفظ version.
6. نشر version المحفوظ فقط.
7. فحص deployment status و`/api/radar` بعد النشر.

## 19. تعريف «منتهٍ»

لا يُغلق المشروع نهائيًا إلا عندما:

1. تُثبت مطابقة القاموس والواجهة مع المرجع القديم.
2. تُطابق الدرجات والتصنيفات والبوابات على golden dataset نفسه.
3. تظهر شركات مؤهلة فقط عندما تكون أدلتها مكتملة.
4. يكتمل الفحص دون تعليق أو ضياع عند إغلاق الهاتف.
5. يصل إشعار الإكمال إلى جهاز فعلي.
