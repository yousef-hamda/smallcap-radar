## ما ثبت من الموقع المرجعي

- الصفحة المرجعية تستخدم `lang="ar"` و`dir="rtl"` وmanifest داكنًا بلون أساسي قريب من `#09090b`.
- السلوك المرئي القديم كان أربعة تبويبات، بينما المطلوب النهائي الحالي يقصر الوجهات على: القيمة الأساسية، فرص الارتداد، المفضلة.
- المسارات الداخلية القديمة ليست REST عامة؛ طلب `/api/radar` على الموقع القديم يعيد 404، والواجهة تستخدم Server Functions مجمعة. لذلك لا يمكن ادعاء إعادة استخدام API قديم.
- الأصول المجمعة تثبت نصوص/إحصاءات المنهجية القديمة، لكنها لا تثبت المعادلات الكاملة لصيغة inflection أو death-spiral أو كل عامل من عوامل التقييم.
- تعذر تنفيذ فحص DOM تفاعلي عبر متصفح مضمّن في هذه البيئة؛ لا توجد أداة Browser callable ضمن الجلسة. تم استخدام HTTP/HTML/الأصول والتحليل الساكن بدل الادعاء بتنفيذ تفاعل لم يحدث.

## baseline الإنتاج

- `GET /` استجاب بعد محاولات متقطعة؛ كانت هناك محاولة سابقة أعادت Site not found ثم عادت 200، ما يحتاج smoke test بعد كل نشر.
- `GET /api/radar`: نحو 26.4MB وزمن نحو 12.7 ثانية. سجل Worker أظهر تجاوز حد الذاكرة وإلغاء طلب.
- `GET /api/company?symbol=DOMO`: نحو 120KB وزمن نحو 14.4 ثانية.
- `GET /api/export?kind=spec`: نحو 1.6KB وزمن نحو 8 ثوانٍ.
- سجلات Worker أثبتت أن baton الخلفي كان يعيد HTTP 401 في محاولات متتابعة.
- `strategy_runs` كان يخزن universe كاملًا داخل صف واحد؛ هذا يزيد حجم القراءة ويجعل سجلات D1 صعبة العرض.
- الاختبارات الحالية لا تغطي أداء 2,000/10,000/15,000 سهم، ولا fault injection شاملًا، ولا وصول push حقيقيًا إلى جهاز فعلي.

## الفجوات المنطقية المكتشفة

1. كان `scanner.ts` يعيد تعريف حدود Core/Bounce بدل استيرادها من عقدة واحدة.
2. كان متوسط حجم 10 أيام × السعر يُخزن كأنه وسيط dollar volume لـ20 يومًا؛ هذا أصبح الآن غير صالح للـPASS، ويظل `UNKNOWN` حتى تتوفر 20 جلسة فعلية.
3. كان EV/S يعامل الدين غير الموجود كصفر؛ أصبح يتطلب مكونات الدين المطلوبة بدل تحويل الغياب إلى رقم.
4. كان عداد Frames يخلط الـ13 baseline مع بدائل IFRS الثلاثة؛ تم فصلهما في نتيجة الـbulk وفي سجل الحدث.
5. كان `historicalMarketData` يعيد cached bars دون قصّها عند `asOf`؛ أصبح يمنع الأشرطة المستقبلية.
6. كان فشل التاريخ في مرحلة 10 يمكن أن ينتهي بحالة `complete`؛ أصبحت أخطاء جلب التاريخ تحافظ على `partial` مع عداد فشل.
7. كان `/api/radar` يعيد كل snapshot/evaluation دفعة واحدة؛ أصبح العقد يدعم `strategy`, `limit`, `offset` ويعيد الصفوف المؤهلة أو المفضلة فقط مع ملخص counts، مع الاحتفاظ بالـrun النشط.
8. كان internal baton يعتمد فقط على `BACKGROUND_SCAN_SECRET`؛ أصبح يستخدم هذا السر من البيئة، أو مفتاح VAPID الخاص الموجود أصلًا في البيئة عند غياب السر الاختياري، دون قيمة ثابتة داخل المصدر.
9. كان endpoint التصدير يعيد state واسعًا افتراضيًا؛ أضيف `kind=audit` لتصدير summary وسجل الأحداث والمواصفة hash دون payload ضخم.

## قيود لم تُحل بعد

- لا توجد مجموعة golden immutable من نتائج النظام القديم لكل رمز/درجة/تصنيف.
- لا توجد قاعدة delisted تاريخية، ولا backtest survivorship-free كامل، ولا holdout مستهلك قابل لإعادة الإنتاج.
- صيغ inflection وdeath-spiral وتطبيع عوامل Core غير موجودة كمعادلات أصلية قابلة للإثبات؛ لا يجوز ملؤها بتخمين.
- مزود الأخبار/الأهداف الحالي لا يثبت average analyst target أو earnings surprises أو backlog.
- إشعار Web Push مولد وموقع ومختبر خادميًا، لكن وصوله الفعلي على Android وSafari/iPhone يحتاج جهازًا فعليًا.
- لا توجد أداة متصفح callable في هذه الجلسة، لذلك لا أضع نتيجة pixel-diff أو ادعاء Safari/Chrome device QA.
- المستودع remote داخلي لـSites وليس GitHub؛ لا توجد قدرة مثبتة على إنشاء repository جديد أو دفعه إلى حساب المستخدم.

## قاعدة الحكم

لا تُسمى النسخة مطابقة كاملة. المطابقة البصرية الجزئية، نجاح build، أو وجود API لا تثبت تطابق الأرقام أو السلوك التاريخي. يبقى السهم خارج القائمة الرئيسية إذا كانت أي بوابة `UNKNOWN` أو `FAIL`، وتظل البيانات المؤرخة fallback موسومة كمصدر fallback لا كبيانات live.
