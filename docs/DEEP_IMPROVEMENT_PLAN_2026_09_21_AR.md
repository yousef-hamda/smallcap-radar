# خطة التحسين العميقة — 21 سبتمبر 2026

هذه الخطة تسجل ما تم تدقيقه وما تم تنفيذه، وتفصل بين منطق الفئة، جودة البيانات، تجربة الاستخدام، وما يحتاج إلى تحقق تاريخي قبل تحويل الدرجة إلى توقع.

## 1. تدقيق الفئتين

### Core — القيمة الأساسية

هدف الفئة هو العثور على شركة صغيرة قابلة للتنفيذ لديها نشاط تجاري مثبت وتقييم مبيعات معقول وربحية أو تدفق نقدي موجب، مع تقليل مخاطر التمويل والتخفيف. لذلك يجب أن تكون العضوية تقاطعية: فشل أي بوابة يخرج السهم من قائمة Core، ولا تستطيع الدرجة تعويض فشل أو نقص الدليل.

البوابات الحالية هي: سهم عادي مدرج، قيمة سوقية بين 25 مليون و2 مليار دولار، وسيط قيمة تداول 20 يومًا لا يقل عن 150 ألف دولار، إيراد موجب، EV/S لا يتجاوز 10، ربح صاف أو FCF موجب، مراجعة موثقة لمخاطر دوامة التمويل، أدلة حرجة مؤرخة، حداثة السعر والفترة المالية، وعدم وجود تعارض موثق.

ترتيب المؤهلين يستخدم 100 نقطة: التقييم 24، الجودة 19، انضباط الأسهم 15، الحجم والسيولة 14، النمو 7، شراء المطلعين 7، اتجاه الهامش 6، نقطة الدخول 5، والميزانية 3. التقييم يعتمد EV/S الموثق للفئة؛ لا يستبدله P/S داخل العامل لأن ذلك يخلط بين قيمة المنشأة وقيمة حقوق الملكية. عامل انضباط الأسهم لا يعطي نقاطًا إلا بعد مراجعة التجزئة.

### Bounce — فرص الارتداد

هدف الفئة هو ارتداد قصير الأجل بعد هبوط حاد، وليس شراء سهم رخيص بالمعنى الأساسي. لذلك لا يكفي انخفاض العائد؛ يجب اجتماع هبوط 12 شهرًا أقل من −35%، خروج لا يقل عن 10% من قاع 52 أسبوعًا، إغلاق أعلى من MA30W بنسبة تتجاوز 5%، تخفيف أقل من 25% بعد مراجعة التجزئة، وسيولة وقيمة سوقية قابلتان للتنفيذ.

الترتيب يستخدم عمق الهبوط 25، قوة الانعكاس 25، السيولة 20، انضباط الأسهم 15، موضع السهم فوق القاع 10، والحجم 5. هدف +20% ووقف −15% وخروج ثلاثة أشهر هي سياسة متابعة مستقلة، وليست احتمال نجاح. السهم الذي لا يملك سعرًا أو MA30W أو قاعًا بدليل مؤرخ يبقى UNKNOWN.

### إصلاحات منطقية منفذة

- عامل Core لا يمنح قيمة تقييم عند غياب EV/S أو يستنتجها من P/S.
- كل مدخل يستخدمه ترتيب Bounce، ومنه السعر ونسبة الأسهم، يُفرغ عند غياب دليل صالح؛ لا يسمح ترتيب قديم أو قيمة غير موثقة بتسجيل نقاط.
- أضيف حد تخفيف خاص بـ Core بدل إعادة استخدام حد Bounce ضمنيًا.
- بقيت حالات UNKNOWN منفصلة عن FAIL: المعلومة المفقودة ليست حكمًا سلبيًا.

## 2. العربية ومحتوى ملف الشركة

تُحفظ المادة الأصلية ومصدرها، ثم تُضاف حقول عربية مستقلة: اسم الشركة، الوصف، القطاع، الصناعة، وعنوان الخبر واسم مصدره. الترجمة تُنفذ عند بناء الملف العميق مع cache داخل الذاكرة لمدة 24 ساعة وحد أقصى للحجم، وتستخدم مزود ترجمة عربي best effort. عند تعطل المزود يظهر النص الأصلي مع رسالة صريحة بدل اختراع ترجمة أو إسقاط الخبر.

يجب إبقاء `title` و`description` الأصليين لأغراض التدقيق، واستخدام `titleAr` و`descriptionAr` في العرض العربي. أي رقم أو تاريخ أو رابط لا يمر عبر الترجمة؛ يبقى من المصدر وبنفس الدليل الزمني.

## 3. خريطة توزيع المحفظة

تم استبدال التقسيم الثنائي المخصص بخوارزمية squarified treemap القياسية. كل مساحة مستطيل تساوي قيمة المركز من إجمالي القيمة المعروفة، والخوارزمية ترتب المراكز تنازليًا وتملأ صفوفًا بأفضل نسبة أبعاد ممكنة. بعد الحساب تُقص الإحداثيات إلى حدود 0–100 لتمنع خروج أي بلاطة من الإطار عند أخطاء التقريب.

قواعد العرض:

- لا تُرسم المراكز بلا سعر على الخريطة حتى لا تتحول البيانات الناقصة إلى وزن صفري مضلل.
- كل مركز يظهر في قائمة أسفل الخريطة مع الشعار والرمز والاسم والوزن، حتى لو كانت بلاطته صغيرة.
- أحجام البلاطات تستجيب لقيمة المركز، وارتفاع الخريطة يتغير حسب حجم الشاشة.
- الشعار يُطلب من same-origin resolver مع cache المتصفح ومزودي FMP وClearbit وParqet، ثم fallback واضح عند غياب شعار منشور.

## 4. جودة الواجهة

المعايير المطبقة هي RTL أولًا، أهداف لمس لا تقل عن 44px، تباين واضح، حالات focus، نص أصلي مساعد عند توفر الترجمة، وعدم الاعتماد على اللون وحده. الرسوم لا تستخدم نقطة أو مسارًا من بيانات غير صالحة، والخريطة لا تعتمد على hover لعرض معلومة أساسية.

## 5. بوابة التحقق

بعد تثبيت الاعتماديات يجب تشغيل:

1. `npm run typecheck`
2. `npm run test:engine`
3. `npm run test:research`
4. `node --test tests/*.test.mjs`
5. `python tests/test_database.py`
6. `npm run lint`
7. `npm run build`

يجب فحص ثلاث حالات محفظة: مركز واحد، أوزان شديدة التفاوت، ووجود مركز بلا سعر. ويجب فحص ملف شركة فيه وصف وأخبار إنجليزية وملف آخر يفشل فيه مزود الترجمة. لا يُعتبر نجاح الترجمة دليلًا على صحة الاستثمار، ولا يُعتبر نجاح البناء دليلًا على صحة المزود الحي.

## 6. أعمال لاحقة لا يجوز تخمينها

- بناء dataset Point-in-Time مع الشركات المشطوبة وإعادة اختبار أوزان الفئتين قبل نشر احتمال ربح.
- قياس تغطية الترجمة وزمنها ومعدل فشلها على مزود الإنتاج، ثم استبدال endpoint العام بمزود موثق إذا أصبح ذلك متاحًا.
- تسجيل مصدر الشعار النهائي في metadata عندما يعاد حفظ ملف الشركة، بدل الاعتماد على الاستدلال من الموقع فقط.
- اختبار بصري فعلي للهاتف وسطح المكتب؛ اختبارات SSR والهندسة الحالية لا تثبت تطابقًا بصريًا كاملًا.
